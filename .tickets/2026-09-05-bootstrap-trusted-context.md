# Bind receiver identity to held trusted configuration

Status: implementation contract; native runtime integration pending.

The fleet bootstrap candidate now has canonical target configuration, request
and result codecs, deterministic receiver packaging, permission inspection and
an anchored read boundary. They are separate primitives. Without one held
context that joins the measured receiver artifact to its fixed sibling config,
a dispatcher could accidentally accept caller identity or cached policy without
rechecking the files that supply its authority.

The next bounded slice composes those primitives. It must retain both native
file contexts, hash exact held bytes, require the declared receiver path and
digest, and revalidate local policy and node/config bindings at every use. It
does not install, start, stage, dispatch or prove live enrollment. A private
same-handle permission accessor prevents callers from reopening a path to fill
the identity response.

### Trusted receiver configuration context contract

T004.10 joins the existing anchored reader and pure target configuration.
It is still read-only: no request dispatcher, staging, install, supervisor,
transport, environment lookup or permission mutation is introduced.

- Export open_receiver_context(receiver_path: str) as a context manager in bootstrap_shim.py. Its one path is a trusted launcher input, never a frame/bundle field. Require the existing exact native canonical path grammar and derive only the literal bootstrap-target.json sibling with the native path class. No cwd, environment, path search, resolve, sys.path modification, guessed filename extension or candidate import is permitted. The later fixed main will obtain its artifact path from its own zip loader; this slice does not implement main.
- Use ExitStack to retain both open_trusted_file contexts for the entire receiver context. Receiver cap is 1 MiB and require_readonly=true; config cap is MAX_TARGET_CONFIG_BYTES and require_readonly=false. Open the receiver first, then its sibling. Failure in either open, parse or validation closes both and all their ancestors. These files may not alias: require distinct canonical paths, and the anchored reader already rejects hardlinks. The receiver filename itself must not equal bootstrap-target.json under native case rules.
- Read both through read_verified, parse config only with BootstrapTargetConfig.from_bytes, and require config.receiver_path equal the launch path exactly, config.platform equal the actual supported native platform and config.receiver_sha256 equal SHA-256 of the measured receiver bytes. A changed/mismatched receiver path or hash uses receiver-mismatch; platform mismatch uses unsupported-platform. Do not independently validate candidate ZIPs here: the preprovisioned artifact's exact bytes are measured, never executed or imported by this helper. A parser-valid config does not prove the executable/supervisor/install roots exist; those checks belong to activation.
- Keep the entry receiver and config digests privately. Yield a private state-only-repr object with read_config(frame: BootstrapReceiverFrame) -> BootstrapTargetConfig and identity(frame: BootstrapReceiverFrame) -> BootstrapReceiverIdentityResult. Expose no file handles, filesystem paths, raw bytes or generic public dictionary through its repr. Returned BootstrapTargetConfig is the existing explicitly private immutable value, not an output envelope. Methods after context exit refuse with precondition-failed. No partially initialized context escapes.
- Before either method returns, revalidate the exact frame using its existing to_dict validator and reread both held files with read_verified. Compare their bytes against the entry digests, reparse the config, and repeat the native-platform, receiver-path and measured-receiver checks. Never trust a cached mutable config or caller-supplied replacement. Require both local bootstrap_enabled and bootstrap_authorized true; false policy uses authorization-denied. Require frame.expected_node equal the trusted local expected_node; mismatch uses receiver-mismatch. Every non-identity frame must also match the measured target_config_sha256 or refuse with receiver-mismatch. Do not compare an opaque plan digest with a nonexistent local plan; durable operation binding owns that later check.
- Add a private permission_verified() method to the anchored file object, not a descriptor property. It runs the existing before/after identity and ancestor validation around a fresh same-descriptor inspect_opened_permissions call, enforces that object's required permission policy, and returns only the exact verdict enum. A denied, unsupported, indeterminate or drifting observation refuses using the reader's existing fixed errors. It never reads by path or changes content/position. The context calls this on both held files after verified reads and again before emitting identity. Owner-writable config remains permitted; receiver must be owner-readonly.
- identity accepts only IDENTITY; other valid operations use invalid-contract. It uses the same read_config checks, then returns the existing exact success identity result with trusted node, measured receiver/config digests, measured permission verdicts and null error. It does not fabricate identity-error/protocol-error frames. All failures raise fixed input-free BootstrapContractError without native exception chaining; the later dispatcher owns bounded result conversion and must not guess an identity when the trusted context could not be established.
- read_config accepts all five canonical frame operations. It validates local policy, expected node and non-identity config binding but does not authorize a lifecycle transition, persist an operation, verify a bundle, inspect a supervisor, start a process or claim installed controller identity. Keep those responsibilities explicit in docstrings and the ticket.
- Native temporary-file tests cover successful repeated identity and stage-bound config reads, exact literal result fields/digests, owner-writable config, readonly receiver, wrong node/path/digest/platform, disabled flags, changed config binding, malformed/noncanonical/oversize config, receiver/config content drift, permissions drift and post-close refusal. Use existing disposable ACL/mode helpers; never change repository/operator permissions. Inject each open/read/parse failure and prove handles close. A fake anchored reader may exercise cross-platform error matrices, but must not replace native happy-path tests.
- An isolated subprocess test builds the existing five-entry zipapp from the real validator and receiver source plus a test-only entrypoint, launches Python with -I -S and a poisoned cwd/PYTHONPATH, opens a temporary canonical sibling config and emits an identity frame. Assert no installed candidate/topology/controller import is required and decode the exact emitted bytes with the canonical result codec. Test-only receiver code may expose a fixed main solely for this fixture; no production main or arbitrary argument surface is added. Skip only other-OS native branches; classify missing Windows link privileges separately. No live enrollment or deployment is claimed.
