Release readiness is the missing skill

anvil-serving-release-readiness turns the 0.21.0 controller outage into a staged gate: manifest-derived container file closure, exact Windows/Mini/Dark/controller/router version parity, rollback, real Pi/OpenClaw smokes, and no closure while an outage remains.

The generic theme counts require care: safe host/environment mutation (1 session, 4 hits), progress visibility (1, 2), risk-tiered verification (1, 1), and evidence discipline (1, 4) are supported. Concurrency isolation is a false positive because lease matched inside release; merge/base safety has zero corpus evidence.

Now · 1 sessions

Safe host and environment mutation

Host, serve, WSL, Docker, and environment changes need computed defaults, gates, and rollback.

Actions

  • Route risky host mutations through verbs with compute, explain, gate, apply, verify, and rollback steps.
  • Require confirm/force for unattended-fatal operations.
  • Stop retrying destructive global operations after one failed attempt and diagnose instead.

Missing tools

  • Reversible host mutation transaction.
  • Destructive-op circuit breaker.

Progress visibility for long autonomous runs

Operators need heartbeats that distinguish healthy waiting from stalled or wedged work.

Actions

  • Emit periodic progress with elapsed time, current phase, last action, and next timeout.
  • Define stuck-state rules for no-output, retry loops, and external health waits.
  • Surface active agents and their current phase in a compact status view.

Missing tools

  • Workflow heartbeat bus.
  • Stuck detector.

Concurrency isolation and leases

Concurrent work needs structural isolation, distinct actors, lease renewal, and a task-loop state machine.

Actions

  • Launch write-capable concurrent agents in isolated checkouts.
  • Track file scopes before dispatching parallel work.
  • Represent the task loop as explicit state, not operator memory.

Missing tools

  • Worktree lease manager.
  • File-scope conflict planner.

Risk-tiered independent verification

Independent review catches defects, but max-depth review should be reserved for high-risk work.

Actions

  • Classify work by blast radius before implementation and assign a review tier.
  • Move spec-independent breakage probes into the first verification pass.
  • Track defects found per review tier so the policy improves over time.

Missing tools

  • Review budget estimator.
  • Defect yield tracker by review tier.

Now · 0 sessions

Merge and base safety

Clean textual merges are not enough; stale bases and held PRs need freshness checks and merged-tree tests.

Actions

  • Fetch before branching and before review.
  • Rebase and retest any PR whose target moved while it was held.
  • Test the exact post-merge tree before merge when the blast radius is high.

Missing tools

  • Base freshness sentinel.
  • Post-merge sandbox runner.
