# Skill improvement: Anvil Serving bindings

At campaign closure, a material process failure, or an explicit improvement
request, use `session-improvement-loop:skill-improvement` from the installed `session-improvement-loop`
plugin. Resolve it through host skill discovery; see
`docs/OPERATOR-SKILLS-AND-SUBAGENTS.md` in the product checkout for installation.
The shared skill owns proposal, independent evaluation, adoption, cost, and
lesson expiry. This reference supplies the Anvil-specific bindings.

- Keep skill instruction revisions distinct from checkpoint, quant, runtime,
  recipe, request, and workload revisions. Model settings use
  [configuration-search.md](configuration-search.md).
- Use the existing friction log and evidence index. Link observation, scope,
  baseline/candidate identities, independent results, reviewer, cost,
  disposition, and expiry; do not add a parallel database or native schema.
- Keep active qualification cells frozen. Changes start a new instruction
  identity. Required correctness, reliability, capacity, restoration, client
  propagation, and publication gates stay with the qualification/publication
  skills; an improvement experiment cannot weaken them.
- Bind the shared budget to the user's limit and reserve enough to finish the
  requested model outcome, authorized restoration/promotion, and reporting.
- Follow the repository's agent roles, including independent review of Astra
  changes. Load the shared Astra reference only when Astra is involved.
- Keep raw diagnostics in protected operator evidence and sanitized findings
  in product documentation. This loop grants no live lifecycle, promotion,
  account-memory, or unrelated-instruction authority.

If the shared skill is missing, resolve an authorized installation or verified
plugin source. Retain the lesson as an unevaluated proposal and continue
campaign closure; absence of an optional learning helper must not block it.
Do not claim independent validation or adoption without completing the method.

The [research review](../../../docs/benchmarks/skill-improvement-research.md)
records the original rationale and the later portable extraction.
