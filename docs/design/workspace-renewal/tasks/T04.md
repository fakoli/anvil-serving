## Implementation steps

1. Inspect current navigation toggle and responsive styles; extend rather than add a second menu implementation. Identify the actual HTML entry file before editing if packaging changes its name.
2. Move global destinations into an accessible hamburger drawer with optional desktop pinning. Rename the Playground display label/page title to Pi while preserving `#/playground` and existing bookmarks. Keep local project/thread navigation independent.
3. Separate page data loading from optional fleet/HUD telemetry and update status regions without replacing active page DOM. Preserve routes, selection, focus, scroll and drafts.
4. Scope persistence to ordinary UI preferences. Do not store prompts, credentials or transcripts in browser storage.

## Acceptance

- [ ] Keyboard and touch can open/close/navigate the drawer; Escape returns focus and mobile background is inert.
- [ ] At narrow and wide widths the composer stays reachable and panes do not force horizontal page overflow.
- [ ] A failed fleet read shows a status warning while Playground and Anvil Work remain usable if their own source is healthy.
- [ ] Existing bookmarks resolve and a HUD update does not erase draft text or interrupt a running session.
