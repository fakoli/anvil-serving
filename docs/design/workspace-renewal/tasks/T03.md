1. Adopt the project/root/thread/worktree contract in PLAN.md using existing identifiers and policy helpers. Define one primary, stable root IDs, owner runtime and access modes; migrate checkout-only config without changing project IDs.
2. Implement bounded directory/text/diff/worktree reads through the selected owner. Reuse Pi Web facilities where they satisfy authorization; extend the owning service if they do not. UI visibility is not filesystem isolation.
3. Bind actual session cwd and permitted roots, including managed sandbox mounts. Implement explicitly selected writable secondary roots via T03d–f; retain read-only defaults for unselected roots. Never pass a browser path directly to the runner.
4. Expose selection of declared roots and primary designation in project settings. Validate deduplication, missing roots, non-Git roots and root changes while a session is active. Keep existing active bindings stable.

Host-mode roots are navigation/context only unless T02 proved tool confinement.
Keep legacy sessions unassigned and owner-only until explicitly associated with
verified declared roots; association changes no native session permissions/cwd.

## Acceptance

- [ ] A project with two directories has exactly one primary; a new thread starts there and can use its authorized secondary context.
- [ ] Traversal (including encoded forms), symlink escape, CRLF, special/secret files, oversized reads and cross-project requests fail at the backend. Leading-dash/metacharacter filenames must either be safely handled as literal data or explicitly rejected; they must never become flags or commands. Test read/write distinctions through actual tool execution in a disposable scoped sandbox. Host mode must instead visibly disclose operator-account tool access and must not claim these restrictions.
- [ ] Changing primary affects new threads without moving existing sessions or shared branches. A single-root legacy config behaves identically.
- [ ] Explorer/worktree labels reflect the selected execution workspace, not a similarly named checkout.
- [ ] An isolated task edits primary plus an explicitly selected writable secondary Git root, while an unselected secondary remains read-only. Conflicts/expired authority block the whole write session; patches, review digests and verification results identify each root. Partial acquisition/transfer failure remains recoverable and cannot report task completion.
