## Implementation steps

Run one slice per agent turn, in order; use the shared receipt rules.

| Slice | Owned change | Checkpoint before continuing |
|---|---|---|
| T06a | One missing-run owner and bounded list/projection adapter | Trace representative owner record to authorized API row/artifact; one operation plus benchmark fixture; native ID/correlation tests |
| T06b | Workbench list/detail/filter and polling lifecycle | First-owner browser journey, 10s/5s budgets, hidden/resume, hung-owner deadline, selection preservation |
| T06c | Remaining declared owner coverage, pagination/backfill and compare | >100 rows, stable snapshots, authorization/cache isolation, compatibility checks; complete packet acceptance and coverage inventory |

1. Identify representative newer runs missing from the UI, their authoritative owner and supported enumeration. Start with operation records plus the actual missing benchmark owner; explicitly inventory Pi/task and imported-evidence coverage.
2. Implement a bounded read projection with namespaced IDs, source provenance, timestamps, native/normalized states, correlation and artifact links. Add owner-side list support if needed rather than querying foreign databases.
3. Authorize before aggregating counts/filtering/pagination; dedupe only explicit operation/job correlations. Preserve historical evidence as imported, including failures/incomplete runs.
4. Replace the overview with active/recent lists, filters and stable detail links; preserve experiment launch. Incrementally poll visible activity and retain selection/scroll; report per-source freshness/partial failures.
5. Make Compare require compatible measurement dimensions. Do not interpret operational verification or completed chat as model quality/promotion.

## Acceptance

- [ ] A synthetic CLI-created benchmark and UI-created operation appear without config edits; explicitly correlated representations produce one logical row.
- [ ] The representative previously missing retained run appears from its owner. If inaccessible, record the exact coverage blocker and keep this criterion pending; explaining the omission is not a completed discovery fix.
- [ ] New-run discovery is within 10 seconds and active updates within 5 seconds while visible; hiding pauses requests and returning refreshes immediately.
- [ ] Pagination crosses the prior 100-row limit without gaps/duplicates; equal timestamps and owner ID collisions are tested.
- [ ] One hung source hits its independent deadline, releases its in-flight slot and leaves last-good rows marked stale while healthy sources continue meeting refresh budgets; unauthorized runs do not leak through rows, counts, cursors or cache.
