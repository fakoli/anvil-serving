# H3 pipeline evidence — stage 1, 2026-10-26

Evidence for a fully local, three-host podcast made from storyboards and recorded host audio/video. This is a research nomination, not a deployed configuration or local qualification. Access date: 2026-10-26 UTC. Publisher claims, firsthand community measurements, source-code facts, supplied local measurements, and estimates are distinguished below.

## What is demonstrated, and what is not

The supplied local baseline uses the Cobijada community merge, pruned INT8 ConvRot, and already renders an accepted-looking 864×480 / 124-frame / 24-fps / 20-step H3 clip in 143.78 seconds, peak 31,402 MiB, and a guided 1728×960 finish in 182.76 seconds, peak 30,106 MiB, using 25,000-token tiles, denoise 0.1, two Euler steps and rank-64 guide LoRA. These are parent-supplied measurements, not rerun here. They do not yet demonstrate host identity, three-speaker attribution, recorded-audio lip sync, consistent studio geometry or long continuity.

The strongest technical next configurations are native multiframe Ref2VA, Hand-Tie motion_context with locked master audio, PDD/Ref8 staged generation, quantized ControlNet-Union 2.0, and source-performance Character Swap V1.5/Relay. The current guided upsampler can remain the finishing reference. No retrieved result qualifies the complete three-host podcast.

There is a separate license mismatch: the current published standard H3 license excludes the United States. Personal/noncommercial use is not an exception in the text. This report records the supplied United States/no-separate-permission condition; it does not ask again or propose proceeding around the license. Technical “worth testing” below means a research nomination conditional on an authorized setting.

## Five configurations worth investigating

### 1. Native Ref2VA multiframe + smaller encoder — worth testing first, technically

**Purpose:** Establish storyboard/camera/three-host identity behavior with the least extra orchestration.

Use [official multiframe template](https://github.com/Comfy-Org/workflow_templates/blob/67984637eefcd4825dcf5c134e39034785be1682/templates/video_minimax_h3_multiframe_reference.json), template repository commit `67984637eefcd4825dcf5c134e39034785be1682` (2026-10-22), and [original multiframe documentation](https://github.com/Comfy-Org/docs/blob/main/tutorials/video/minimax/minimax-h3-multiframe.mdx). Template defaults: Ref2VA pruned INT8 ConvRot, Qwen3-VL-32B NVFP4+AWQ, INT8 video VAE, FP32 audio VAE, 0.4 MP / 864×480, 124 frames, 20 steps, res_multistep/simple, 24 fps, optional Turbo off. Feed each host's face/views and studio plate as semantic references; AddGuide anchors storyboard images at explicit frame indices. At 24 fps, 1.5 seconds → frame 36. This is a proposed podcast input mapping, not a tested three-person recipe.

Decisive documentation passage: “not visible to the text encoder”. Images connected only to AddGuide need an additional ref_images connection if Qwen should interpret their numbered identity/scene tags. The example's initial image is a semantic reference; there is no frame-zero AddGuide. Add one when an actual opening composition must be pinned. Four-step Turbo is explicitly described as losing some audio/motion quality.

Memory: published NVFP4 encoder file is 14.610 GiB versus supplied incumbent INT8 encoder 25.277 GiB, a calculated 10.667-GiB reduction in stored weights. It can ease host staging and encoder residency, but it cannot be assumed to lower a sampler-bound 31.4-GiB peak by the same amount. Reference-image/video token costs remain unknown on this machine. Start with three small face references plus one studio image, then add views individually; this is a diagnostic proposal.

A subsequent W6A8 DiT arm reduces stored generator weights 19.530→14.886 GiB, about 4.644 GiB. [Kitchen PR191](https://github.com/Comfy-Org/comfy-kitchen/pull/191) merged 2026-09-23 at `e33c9bdb7042bb78e2609c7632878f1844490166`; [core PR16483](https://github.com/Comfy-Org/ComfyUI/pull/16483) also merged, `491bf3b928db565328292f83268d00af57867786`. PR191 measures one real H3 out_proj layer on RTX5090, M=4096: INT8 output relL2 0.0150/0.477 ms, W6A8 g32 0.0256/0.627 ms, W4A8 g16 0.0738/0.664 ms. This demonstrates a weight/error/memory trade, not equal video quality or an end-to-end speedup. Keep INT8 as quality control.

### 2. Hand-Tie motion_context + master audio + restart cuts — worth testing; hand_tie is watch

Pin [Hand-Tie Clips](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/tree/073104edd381b7b56d2f2ae80bbe3d9578f764ed), commit 2026-10-25, release changelog 3.0.0 dated 2026-10-18. [README](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/blob/073104edd381b7b56d2f2ae80bbe3d9578f764ed/README.md) describes nine reference stills, three reference videos, three voice clips, per-hop camera/framing and cached retakes. Its master recording is the relevant feature for already recorded podcast speech.

**Recipe constraint verified in code:** `pin_mech=motion_context` or auto; `master_audio_file` set; `realism_boost=off`; `audio_refine=off`. [h3_ref_chain.py](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/blob/073104edd381b7b56d2f2ae80bbe3d9578f764ed/h3_ref_chain.py#L4887) rejects hand_tie with “does not take master_audio_file yet”; subsequent guards say “realism_boost does not run with master_audio_file” and “audio_refine does not run with master_audio_file”. The README's feature list is not permission to combine every feature. Code encodes the master recording, replaces/fixes its audio latent and leaves video denoising active. [audio_lock.py](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/blob/073104edd381b7b56d2f2ae80bbe3d9578f764ed/audio_lock.py) computes overlap-aware audio windows and explicit restart accounting. Passthrough of the recording preserves sound, not proven mouth accuracy.

[CHANGELOG](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/blob/073104edd381b7b56d2f2ae80bbe3d9578f764ed/CHANGELOG.md) publisher evidence: continuous relays last roughly 5–6 Turbo hops or 7–8 non-Turbo refined hops before texture changes; restart cuts reset context. The 10-hop hand_tie showcase is 71.7 seconds, 1024×768 at 48 fps, and uses a different experimental previs path. It does not validate master-audio mode or three simultaneous hosts.

[PROMPTING](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/blob/073104edd381b7b56d2f2ae80bbe3d9578f764ed/PROMPTING.md) supplies a concrete two-person failure: short lines went to both mouths on two seeds; assigning the listener a closed-mouth action corrected those same seeds. Five rapid turns remain hard at eight steps. For a podcast, authored cuts to the active speaker are a lower-risk experiment than assuming all three mouths will remain correctly attributed. Studio/camera changes should use restart/hard_cut rather than a continuous join that must morph between incompatible compositions. This is an inference.

RAM/VRAM: no retrieved measured peak for the exact current master-audio/three-host path. The base's ~1.18-GiB free peak margin gives no grounds to claim that three video and three voice references fit. RefMod support stores pooled VAE reference latents and a voice-file association; [implementation](https://github.com/sandpies/ComfyUI-Hand-Tie-Clips/blob/073104edd381b7b56d2f2ae80bbe3d9578f764ed/refmod.py) does not update model weights. It must not be called a trained character LoRA.

### 3. PDD 8 / Ref8 generation with staged refinement — worth testing selectively

[Alibaba PDD Acc model card](https://huggingface.co/alibaba-pai/MiniMax-H3-Acc-LoRAs) supplies separate FL2VA and Ref2VA rank/alpha-64 BF16 adapters; publisher demos compare four/eight NFE at strength 1.0. [LightX2V release inventory](https://huggingface.co/lightx2v/Minimax-h3-Turbo/tree/30f485ed874aa44c8183348ad361c5eabad318da), last modified 2026-10-20, includes Ref2VA 4-step v1.0 and 8-step v1.0/v1.1 at 768p, beyond the old v0.1 shown in Comfy's card. The [ModelTC README](https://github.com/ModelTC/Minimax-H3-Turbo/blob/02e26d591f7a04d5d1a074c9566d5dd4f22f6225/README.md) is older (2026-08-27); its published table does not establish later files' training recipe. Do not transfer shifts automatically across release names. Its old Ref4 v0.1 table uses video/audio shifts 12/3, four Euler NFEs; FL4 v1.0 768p uses 6/3. [Comfy setup](https://github.com/ModelTC/Minimax-H3-Turbo/blob/02e26d591f7a04d5d1a074c9566d5dd4f22f6225/COMFYUI_SETUP_AND_INFERENCE.md) requires ComfyUI≥0.31.0 and matching LoRA/steps/shifts.

Firsthand [5090 lab notes](https://github.com/yuichi-suzuki-highdrama/minimax-h3-local-pipeline-notes/blob/55509fd16464f57512b6c35bf09255d74fa4fdd6/README.md), Windows11/128 GB, Torch2.11/CUDA13, Comfy 0.34.x: Ref2VA PDD 8 at 480p, split references capped near 1024 short edge with max, bake target 768 conditioning once, learned latent upscale to1344×768, cached-condition Ref4 refine Euler CFG1 denoise~0.75, then VSR2×. Eight-second example total353.4s; approximately330s on later clip. These are personal anime-oriented relative measurements, not photoreal podcast benchmarks. Target conditioning retries were reusable; separate stages are the practical contribution.

Contrary results in the same notes: top-k10% sparse Ref4 finishing was faster (~100–120s versus150–160s) but rejected on later clips; PDD4 finishing was grainy, and a PDD 8 denoise0.25 finish took~490s without improving over Ref4. Do not replace the already accepted denoise0.1 guided finish with this more destructive0.75 recipe by default.

Memory: Comfy LightX2V adapter file is 1.822 GiB; Kijai pruned PDD adapter 1.607 GiB. These weight sizes are not measured runtime increases; dynamic LoRA application/offload changes residency. No matched current three-host peak exists.

### 4. ControlNet-Union2.0 pruned INT8 — watch; worth testing if geometry/control remains weak

[Union2.0 card](https://huggingface.co/alibaba-pai/MiniMax-H3-Fun-Controlnet-Union-2.0/blob/7d2c95de2e351ed6a0b360af45f62daa04c26f88/README.md), 2026-09-22, supersedes [v1](https://huggingface.co/alibaba-pai/MiniMax-H3-Fun-Controlnet-Union). V2 adds Scribble/Layout/Gray to Canny/Depth/HED/MLSD/Pose and doubles control layers5→10. Publisher examples:40 steps, guidance1, control_context_scale1, seed43,704×1280 pixel budget,24 fps. Structural maps from recorded performance or a studio previs are plausible geometry controls; they are not identity/lip-sync evidence. The control branch does not apply to audio.

Decisive passage: “Loading a v1 config against this checkpoint is a silent failure.” V2 requires `minimax_h3_control_inpaint_post_norm.yaml`; v1's five-block config drops/misplaces v2 weights. Verify the actual Comfy loader/patch version rather than copying old v1 examples.

Weight fit: original v2 branch is13,551,637,688 bytes=12.621 GiB; plus19.530 GiB DiT exceeds31.843 GiB VRAM before activations. The current Comfy/Kijai pruned INT8 v2 patch is4,531,220,608 bytes=4.220 GiB, so DiT + branch stored-weight sum23.750 GiB, leaving8.092 GiB nominal before other residents/workspaces. This makes quantized/offloaded investigation plausible, not demonstrated fit. Base already uses nearly the card, and ControlNet activations can dominate. V1 quant patch is2.139 GiB, but current publisher recommends v2. No independent matched v1/v2 quality/memory benchmark was found.

Exact intended recipe: Ref2VA INT8, character LoRA strength1, separate FL2V Turbo8v1.0-768p strength1, eight-steps, CFG1, er_sde/normal. V1.5 file155,110,792 bytes=0.144 GiB; SHA256 `8f2c3c3eba161df8d0c6099598b4730f641f5ce01e04cd16d2427cff8a35218f` is published in its [workflow guide](https://huggingface.co/akatz-ai/MiniMax-H3-Character-Swap-LoRA/blob/96ea3407b230b6f7df71c58c70e31df96bd7e533/examples/README.md). [H3 Relay](https://github.com/akatz-ai/h3-relay/tree/e2a7665b6eb8ea37a88c0de2c9c6b69a8f7c9220), commit2026-10-22, uses native Comfy source prep/SAM/reference/sampling with disk-backed accepted windows, rerolls and release barriers. Windows RTX 5090 remains a different platform. For three hosts, qualifying one masked speaker per shot is a smaller initial task than claiming simultaneous three-person swaps.

The [original Relay validation](https://github.com/akatz-ai/h3-relay/blob/e2a7665b6eb8ea37a88c0de2c9c6b69a8f7c9220/VALIDATION.md#L389) is valuable larger-project evidence. This clearly exceeds the supplied64GiBcontainer. Chunked finishing of cached shots later peaked22.25GiBRAM/119.84s. A new ten-shot functional staged graph peaked22.40GiBRAM/23959MiBVRAM, but was deliberately shortened to9.48 seconds total; it is not ten15s-shots or three-host quality proof. The original58s case usedRTX 4090 Linux and a different enhancement stack. Bounded staging is the transferable design evidence; its precise speed/memory is not a promised5090 result.

## Smallest informative qualification proposal (not run)

Use one short real excerpt with three identified hosts and fixed clean studio storyboards, then test one variable at a time: native 20-step Ref2VA with INT8 versus NVFP4encoder; native timeline guides versus Hand-Tie motion_context+master audio; then eight-stepPDD/Ref8; only then a geometrycontrol or source-video swap arm. Keep accepted guided finish unchanged. Score per-host likeness, spoken-word/source-audio alignment, active-speaker correctness, closed-mouth listeners, studio geometry, camera framing, cuts/seams and across-shot drift. Record full cold/warmwall time,peak VRAM,RSS/cgroup/swap and failures. Do not call passing audio passthrough or validMP4 a lipsync pass.

Skipped: deployment, downloads, inference, runtime changes, private media access, inferred benchmarks and exhaustive trainer evaluation. Main risks: license mismatch, narrowmemory margin, speaker/identity drift and unqualified three-host recorded-audio behavior.
