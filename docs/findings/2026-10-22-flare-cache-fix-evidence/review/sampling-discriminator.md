## RNG behavior supported by source

GLM captures init and restore with admission buffers (`ignition/recipes/glm53/bootstrap.py:437-445`). Both use `PreparedAdmission` and apply it after model-state transfer (`ignition/components/maintenance.py:107-117,147-158`). `_admission_finish` assigns the request seed, resets counter/generated to0, and pending token to-1 (`ignition/components/sampling.py:646-675`). The ordinary sampler uses seed plus offset4*counter, independent of physical slot (`sampling.py:447-460`). Speculative target draws use a distinct RNG domain and reset offset on generation mismatch (`ignition/components/speculation.py:387-392,541-553`). Preempted/readmitted requests deliberately derive a continuation seed from original seed and generated count (`helios/src/server/runtime.rs:224-232,1626-1638`). Thus request RNG is initialized anew under prefix restore; it does not resume the previous request's generated-token RNG stream from a prefix checkpoint. This source design is not an empirical guarantee that numerical kernels, graph shapes or speculative paths give identical sampled sequences.
