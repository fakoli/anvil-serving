# Swift-1.5 NInfer on one RTX 5090: secondary promotion and post-promotion benchmark

**Date:** 2026-09-25 UTC
**Measured hardware:** one RTX 5090, 32,607 MiB, Windows 11 / Docker Desktop / WSL2
**Evidence:** functional, bounded quality, descriptive capacity, routed client acceptance; failed long-context concurrency retained
**Decision:** user-authorized deployment as `llm.secondary` at 262,144 total tokens, 32,768 maximum output tokens, and C4 configured admission. The configured C4 limit does **not** establish reliable C4 operation at 128K prompts.

The requested [community post](https://www.reddit.com/r/LocalLLM/comments/1wplkrm/swift15_qwen3827b_on_a_single_rtx_5090_allnvfp4/) supplied a starting profile, not transferable benchmark results. The [pinned publisher artifact](https://huggingface.co/kaushikvira/Qwen3.8-27B-swift15-nvfp4full-dflash2-NInfer-v3/tree/ff891a1130adfcf46bf745e06f0fa3dcde2e8c82) is all-NVFP4 W4A4 plus DFlash2. Its model file SHA-256 is `16f313c043c06a19f7c27d74f8259ed9d86c8cb5beed631efbb96f392b373d96`. The NInfer source is `bace20dc70249eed6402b66d4852c6c3f9612905`; the baked image ID is `sha256:59df48dd99f0d177b73de57ba88eb6457ed7e4b0c5771c45e8976adcd9f5ef67`. The managed [deployment recipe](../../configs/qwen38-swift15-ninfer-dflash2-rtx5090-baked.toml) pins these inputs.

The separately linked [uncensored MTP checkpoint](https://huggingface.co/ajgazin/Swift-1.5-Qwen3.8-27B-Uncensored-MTP) was retained as an alternate lead. It is a different artifact and was not included in this exact-post serve or benchmark.

## Exact profile and necessary adaptation

The deployed recipe retained 262,144 maximum context, K8V4 KV, automatic device KV capacity, DFlash2 K=7 with LM-head draft, vision, a 16K default thinking budget, four-request configured concurrency, 32,768 default output tokens, and a 450 W GPU cap. The publisher card's additional 48 GiB pinned Host KV allocation exceeds this host's 30.91 GiB physical RAM, so the managed recipe uses 2 GiB Host KV and four Host State slots. The pinned engine also rejects the card's `--image-token-budget` argument, which was removed after the first failed startup. The [feasibility record](2026-09-25-swift15-ninfer-5090-exact-recipe-feasibility.md) and [startup logs](2026-09-25-swift15-ninfer-5090-evidence/README.md) preserve the physical calculation and failure.

The final baked load verified the binary and model hashes, loaded 18.0 GiB of weights, allocated 2.00 GiB Host KV and 747.3 MiB Host State, and reported a **282,112-token shared device KV pool**. The community post reported 308,736 shared tokens. Neither number means four simultaneous 262K windows fit. No setting-by-setting tuning ramp preceded promotion: this was one final serve profile, followed by independent functional gates and then benchmarks.

## Promotion and client acceptance

After an exact configuration preview and trusted host identity check, the router selected served model `qwen38-swift15-ninfer-dflash2-c4-262k` for `llm.secondary`. The primary route remained intact as rollback. The new endpoint passed routed smoke, JSON, and tools. Managed harness capture then synchronized Pi, OpenClaw, Hermes, and Open WebUI catalogs across the declared Linux and macOS clients. The fleet repeat reported **changed=0, failed=0, unreachable=0** on each host. The Windows Pi catalog on the measured host also converged (`changed=[]` on repeat), and a fresh Pi session returned a nonce from a tool-read fixture using protected router credentials. A routed Mini OpenClaw/Hermes tool-result suite passed 2/2 with the selected model and exact route fingerprint. These deployment receipts are retained in the private operator record because they include real topology and identities.

## Post-promotion measurements

All capacity cells below used the final serve profile. They sent unique prefixes and request canaries, temperature zero, a 256-word target, and a 512-token response cap. The measured cells disabled thinking per request to expose visible decode; the default-thinking strict scout produced no visible answers within that small response cap. The model did **not** follow the exact 256-word output target (0 exact completions), so the successful `observe` cells are **descriptive throughput**, not strict controlled-output comparisons. They cannot be compared directly with the publisher's 256-token probe or the prior ThinkingCap strict cells. The 128K/C4 failure was traced to the serving engine's **HTTP 503 request queue timeout** in managed logs; no GPU out-of-memory or container crash was observed. The raw benchmark parser initially surfaced these as streams ending without visible content because it ignored SSE error chunks when no observer was attached. The request parser now raises the server error for every consumer, with a regression test. The already-recorded failed artifact remains unchanged and is interpreted using the authoritative managed log. Raising the route concurrency above this measured boundary would need a separate qualified configuration.

A separate routed native context job ran on an isolated benchmark client after the route was live. It passed **18/18** exact-marker cases: six each at 32,718, 130,918, and **257,898 actual prompt tokens**, covering 10%, 50%, and 90% needle positions twice per depth with 4,096 tokens reserved for output. Mean end-to-end latency by depth was 3.49 s, 26.31 s, and 85.46 s. The worker recorded no engine telemetry and could not read the route's configured-context field from that endpoint; the exact route fingerprint and separate installed configuration establish the 262,144-token declaration. The [sanitized native context evidence](2026-09-25-swift15-ninfer-5090-evidence/context-routed-18.json) replaces the real model-host and worker IDs with generic identifiers. Its stage-level hashes refer to private worker sidecars; the native result and raw transport copy are retained privately. This routed C1 result does not repair the failed 128K/C4 cell.

The routed native agentic scout completed **17/18** deterministic cases using the deployment's default thinking behavior and the pinned `scout` profile. One `debug-loop` repetition reached a correct final answer but failed its tool protocol stage after repeated unsuccessful edit attempts; it is a failure, not a pass. The profile's 75% pass floor was met, but this is synthetic agentic evidence rather than a broad coding score. The [native per-case record](2026-09-25-swift15-ninfer-5090-evidence/agentic-routed-18.json) and [sanitized durable-job evidence](2026-09-25-swift15-ninfer-5090-evidence/agentic-routed-evidence.json) retain the exact outcome.

The final image passed direct smoke, JSON, tool calls, streaming, tool-result continuation, Responses, image understanding, and OCR. An independent retrieval probe returned the exact marker at **251,715 actual prompt tokens** with a 4,352-token completion allowance. A baked-runtime repeat passed near the limit. A bounded native chat/tool/session/intelligence suite passed tools 3/3, session 3/3, and two deterministic intelligence checks 6/6; these are small diagnostic cases, not IFBench, GSM8K, or broad coding scores. The pinned 12-case computer-use image/OCR corpus passed **12/12**. The community post's IFBench 69.0, GSM8K 95%, ~160.8 tok/s decode, 200K prefill, and three-depth 250K claims remain **external priors**, not reproduced local measurements.

## Limits and decision

The deployment proves a healthy 262K/C4 **configured** serve, routed use, and several bounded functional paths on one RTX 5090. It does not qualify four simultaneous long windows, strict output adherence, broad coding intelligence beyond the five frozen SWE cases, production reliability, or the publisher's performance numbers. The 128K/C4 timeout is an operational limit even though the alias advertises C4. The earlier ThinkingCap 128K/C1 qualification remains a historical measured control and preserved operator rollback; this finding supersedes its active secondary assignment, not its evidence.
