# Swift-1.5 NInfer post-profile trial on RTX 5090

**Date:** 2026-09-25 UTC
**Evidence class:** direct functional candidate evidence, followed by a separate post-promotion benchmark
**Decision:** the linked model card's 48 GiB Host KV sample is physically infeasible on this host; the adapted profile was subsequently deployed under the secondary alias. See the [promotion and benchmark finding](2026-09-25-swift15-ninfer-5090-promotion.md) for the later decision and limits.

## Requested profile

The [publisher's artifact](https://huggingface.co/kaushikvira/Qwen3.8-27B-swift15-nvfp4full-dflash2-NInfer-v3/tree/ff891a1130adfcf46bf745e06f0fa3dcde2e8c82) is `kaushikvira/Qwen3.8-27B-swift15-nvfp4full-dflash2-NInfer-v3@ff891a1130adfcf46bf745e06f0fa3dcde2e8c82`. Its `qwen3_8_27b_swift15_nvfp4full-dflash2.ninfer` file is 19,782,447,364 bytes, with publisher SHA-256 `16f313c043c06a19f7c27d74f8259ed9d86c8cb5beed631efbb96f392b373d96`. The model card calls for NInfer v3 at or after `98dada0e`; the inspected source revision was `bace20dc70249eed6402b66d4852c6c3f9612905`. The pinned artifact was downloaded into the managed cache; the managed recipe subsequently verified its model-file SHA-256 at startup.

The exact command in the card sets `--max-context 262144`, `--kv-capacity auto`, `--kv-dtype k8v4`, `--max-concurrency 4`, `--default-max-tokens 32768`, `--prefill-chunk 4096`, `--temperature 0.9`, `--min-p 0.05`, `--spec dflash2`, `--draft-tokens 7`, `--lm-head-draft`, `--host-kv-mib 49152`, `--host-state-slots 16`, `--vision`, `--default-thinking-budget 16384`, `--preserve-thinking`, and `--image-token-budget 1280`. Its claimed 308,736-token device KV pool is shared, not four independent 262,144-token pools. The publisher's performance and quality numbers remain external priors.

## Host screen

Anvil Serving's managed status reported one NVIDIA GeForce RTX 5090 with 32,607 MiB GPU memory, 448 MiB in use, split mode with no GPU owner, and no running recipe container. `models cache inventory` reported 404,019,523,584 bytes free in the model cache volume. Independent Windows `Win32_OperatingSystem` inventory reported **30.91 GiB total physical RAM** and **5.71 GiB free** at observation time. These are point-in-time host observations, not a model allocation measurement.

The requested `--host-kv-mib 49152` equals **48 GiB**. [NInfer's serving contract](https://github.com/Neroued/ninfer/blob/bace20dc70249eed6402b66d4852c6c3f9612905/docs/serving.md) calls it a startup-fixed pinned Host KV capacity. The inspected [arena constructor](https://github.com/Neroued/ninfer/blob/bace20dc70249eed6402b66d4852c6c3f9612905/src/core/host_kv_arena.cpp) allocates the complete capacity through `PinnedHostBuffer`, whose [implementation](https://github.com/Neroued/ninfer/blob/bace20dc70249eed6402b66d4852c6c3f9612905/src/core/arena.cu) calls `cudaMallocHost` for that byte count. Thus its minimum pinned host allocation is 48 GiB before 16 host-state slots, the process, Docker/WSL, or the operating system. It exceeds total physical RAM by **17.09 GiB**. This is a physical-capacity rejection of the exact profile, independent of GPU fit or model quality.

## Consequence

The user requested the settings explicitly stated in the community post. Its post did not specify Host KV or Host State capacities; the linked card's sample command uses 48 GiB and 16 slots. A [managed local recipe](../../configs/qwen38-swift15-ninfer-dflash2-rtx5090-post-profile.toml) retains the post's 262K context, K8V4, DFlash2 K=7, vision, 16K thinking budget, concurrency 4, and 450 W cap, while adapting Host KV to 2 GiB and Host State to four slots. The 19.8 GB artifact was pulled at the exact revision and the candidate loaded under pinned NInfer source. The first startup failed because `--image-token-budget`, present in the card example but unsupported by this source revision, was included; the revised recipe removes it. The failed startup and remedy are retained in the [evidence bundle](2026-09-25-swift15-ninfer-5090-evidence/README.md).

The second managed load verified the exact model-file SHA-256 and returned healthy. NInfer reported 18.0 GiB loaded weights, 2.00 GiB pinned Host KV, 747.3 MiB pinned Host State, and a **282,112-token shared K8V4 device pool**, 26,624 tokens below the publisher's reported 308,736. This establishes one healthy serve, not four independent full-context lanes.

Independent direct preflight passed smoke, JSON, one-request and four-request tools, streaming tools, tool-result continuation, Responses, image understanding, and OCR. A retrieval probe passed at **251,715 actual prompt tokens** with a 4,352-token completion allowance; the harness's nominal target was 305,000 and must not be reported as actual context. The earlier nominal-250K probe passed at 206,339 actual prompt tokens. These are functional scouts, not quality or throughput benchmarks. The [native preflight artifacts](2026-09-25-swift15-ninfer-5090-evidence/README.md) carry request-level observations.

A [bounded baked runtime](../../configs/runtime/ninfer-bace20dc-swift15/Dockerfile) was built from the pinned source and a dated Ubuntu package snapshot. Its [immutable image ID and build record](2026-09-25-swift15-ninfer-5090-evidence/baked-build.txt) match the source label. The [baked managed recipe](../../configs/qwen38-swift15-ninfer-dflash2-rtx5090-baked.toml) restarted successfully, checked both binary and artifact hashes, reproduced the 282,112-token pool, and passed the same short direct functional and vision gates. The baked near-limit retrieval repeat subsequently passed.

This feasibility scout did not change an alias. A separately verified router host identity, authorized route installation, fleet reconciliation, and post-promotion measurements are recorded in the [follow-up finding](2026-09-25-swift15-ninfer-5090-promotion.md). The publisher's performance and quality claims cannot be transferred to the adapted profile.
