# Failures and limitations

- **Response-cap starvation is distinct from job exhaustion.** The observed Max
  response-generation limit consumed the shared cap in reported reasoning;
  independent coding grades and whole-job budgets remain separate. Generic
  native exhausted-context labels do not prove that the 327,680-token serving
  context was filled.
- **User traffic remains in service.** The original global-idle preparation
  assumption was amended and independently reviewed before the first diagnostic
  request. All original job specifications and controls remained unchanged.
  The new gate permits bounded owned work alongside users, with successful
  request-accounting closure and worker exit. It does not acquire global
  quiescence or exclusive performance attribution.
- **Historical evidence is a different baseline.** Today's process generation,
  conversation-disk cache policy and 48-GiB serving memory limit differ from the
  November 8 check. Same model and image do not make historical timings a
  matched control. No cache reset, forced user-request cancellation or serving
  change is part of this investigation.
- **The numeric control gap is in Anvil.** TensorFold already supports a native
  request-local thinking budget. The installed Aider controls and relay do not
  carry it. The separately reviewed source proposal is not installed, deployed
  or qualified by these effort-only trials. Offline forwarding/validation
  checks are distinct from an actual forced-budget coding pass.
- **The sample remains small.** One deliberately selected Go task, two planned
  repetitions per effort, unsupported routed seed control and uncontrolled cache
  state do not establish a global reasoning policy or broad quality ranking.
  Process text is omitted in the public projection; complete model prose and a
  semantic-loop diagnosis are not claimed. Effort remains part of the rendered
  token-prefix cache identity; that source contract is not proof of identical
  cache state or stochastic draws.
